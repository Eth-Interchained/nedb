## Summary

**Slice 3b and the `AS OF` prerequisite — which turned out to be one change, not two.** `AS OF` in the evaluator is unreachable until the routing gate widens, and the gate cannot widen before `AS OF` exists, or a time-travel query silently routes to an engine that can't time travel.

`NEDBD_SQL_ENGINE=1` routes user-collection `SELECT`s through the SQL evaluator. **Default off.**

## What the flag unlocks

Live over psql 17.10, on user collections. Every one of these is refused **by name** by the translator today:

```
JOIN / LEFT JOIN         1|Bob  2|Ann  3|Bob
sum() AND avg()          open|40|40    paid|420|210
UNION                    1 2 3 d1 d2
IN (subquery)            1 2 3
DISTINCT                 open paid
expression in select     80 240 600
array_agg(x ORDER BY y)  paid|["3","1"]
```

The two-aggregate row is the one that matters. NQL's grouped row carries the key, `count`, and **one** named aggregate — so `sum(total), avg(total)` was never slow, it was *unrepresentable*. That's the ceiling no translator could clear, and it's gone.

## `AS OF` hangs on the table, not the query

`TableRef::as_of`. Two reasons: it's where PostgreSQL's own grammar would take it (`relation_expr`, the production `table_ref` is built from), and it's the only placement that can express the query worth having — one relation in the past joined against another at the tip.

A sequence, never a wall-clock time, refused in the translator's exact words so a client never learns two answers for the same mistake.

The `AS OF` / `AS alias` ambiguity needed a one-token lookahead: `AS` starts both, and only the word after it disambiguates. Without that, `parse_table_alias` eats `OF` as the alias and leaves `SYSTEM TIME 42` in the token stream.

## A silent wrong answer I introduced, then caught

Recorded because the fix is the interesting part. The resolver is keyed by **name**, so one collection named twice gets one scan. My first version handled that the way 3a handles an ambiguous pre-filter — drop the qualifier rather than guess:

```sql
SELECT o.total, n.total FROM orders AS OF SYSTEM TIME 1 o
  JOIN orders n ON o._id = n._id
```
```
1|999|999          ← both sides returned the CURRENT value
```

For a pre-filter, dropping is right: it costs a wasted row. For `AS OF` it's catastrophic — the historical arm answered from the tip and the comparison quietly stopped being a comparison. **The "don't guess, drop it" instinct is only safe when dropping is a weakening.** Dropping a temporal qualifier isn't a weakening, it's a different question.

Now refused, naming *which* disagreement it is:

```
"orders" is read at the tip and AS OF 1 in one statement...
"orders" is read AS OF 1 and 2 in one statement...
```

…while the same sequence twice still works, because one scan does serve that.

**The second version of that check was also wrong, and its own test found it.** It judged each arm as it walked, so the first arm of a self-join was judged before it had been recorded, and a legitimate pair reported the wrong reason. Sequences are now gathered per name and judged afterwards.

One more consequence: the pre-filter's error fallback had to change. Dropping the pre-filter on an NQL error is free; falling back *without* the `AS OF` would answer a historical question with current data. The sequence now travels with the retry.

## Engine impact

`sqlselect.rs` (`TableRef::as_of` + parse) and `pgwire.rs` (temporal map, conflict refusal, the flag). **Flag-off is verified byte-identical to before:** `JOIN` and `DISTINCT` still refused by name, plain selects, `AS OF` and the catalogue all unchanged.

A statement the evaluator's grammar can't parse — `TRACE`, `SEARCH`, `VALID AS OF`, `TRAVERSE`, every write — still falls through to the translator on its own, because `parse` fails and the gate is never consulted.

## Studio impact

None. Studio talks HTTP/NQL.

## Not claimed

- **Parity is not proven.** The flag exists precisely because the two engines have not been shown to agree across a corpus. That is the next slice, and nobody's production reads should move before it.
- The evaluator still has no `VALID AS OF`, `TRACE`, `SEARCH`, `LINK` or `TRAVERSE` — those remain the translator's, and remain the Slice 4 grammar work.
- `array_agg` renders as JSON `["3","1"]` rather than Postgres's `{3,1}`. Real fidelity gap, not in scope here.
- **Pre-existing, found while verifying:** `EXPLAIN` reports `Seq Scan (actual rows=0)` feeding a `Filter` that reports 1, on the single-relation path — with *and* without `AS OF`, so it predates this change. A scan cannot emit 0 rows and feed 1 upward. Reporting bug, not correctness, and it wants its own PR.
